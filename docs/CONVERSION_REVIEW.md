# Conversion reliability and output discovery

## Changes

- Both engines now write into a unique temporary directory inside the selected
  output folder. The expected Markdown must exist and be nonempty before any
  generated files are published. Images and metadata keep their relative paths.
- Marker no longer recursively scans the entire user output folder or compares
  output timestamps with the start time. Detection is independent of filesystem
  timestamp precision and unrelated exports.
- A zero exit code without the expected Markdown is a failed conversion.
  MarkItDown can no longer mistake a previous export for a new result.
- Failed, timed-out and cancelled processes discard their temporary output and
  preserve previous exports. Successful exports retain the existing replacement
  behavior. Publication is per file, with Markdown last; it is not a transaction
  across every image and metadata file. A publication I/O failure retains the
  remaining generated files and reports their recovery directory.
- Rejected worker submissions release the active conversion slot and return a
  failed future. Cancelling the returned future cannot permanently wedge the
  slot, and does not allow a second conversion while the first engine is running.
  Use `cancelActive()` to request cancellation of the engine itself.
- The development Marker executable now receives `--force_ocr` when selected.

## Validation

Use the pinned release JDK 21. The machine's default Java 26 is incompatible
with this repository's existing Mockito/Byte Buddy version when mocking
`AutoCloseable`; no dependency upgrade is included in this change.

```powershell
$env:JAVA_HOME = (Resolve-Path 'build/tools/jdk-21.0.12.1+1').Path
mvn verify
```

Regression coverage includes missing/empty/stale Markdown, unrelated files,
coarse output timestamps, auxiliary images/metadata, failed-output preservation,
publication conflicts and recovery, rejected scheduling and cancelled futures.
Native JavaFX UI tests remain opt-in.

Validation on 2026-10-02 with the pinned JDK: `mvn verify` reported 114 tests,
112 passed, 2 opt-in UI tests skipped, zero failures/errors. The real smoke
passed for both installed engines: valid PDF conversion, corrupt PDF failure,
previous Markdown preservation, temporary cleanup and zero orphan processes.
The successful process durations were 1.706 s for MarkItDown and 109.825 s for
Marker on the small digital fixture. These are individual smoke observations,
not before/after benchmarks or quality-equivalent engine comparisons. Logs are
in `build/conversion-verify.log` and `build/conversion-*-smoke.log`; machine-local
JSON evidence is under `build/conversion-smoke`.

`ConversionOutputSmoke` exercises an already installed real engine without
installing or repairing it. It copies the supplied fixture, converts that copy,
then corrupts the copy and verifies that the failed conversion preserves the
previous Markdown, removes its temporary output and leaves no child processes.

```powershell
mvn test-compile dependency:build-classpath '-Dmdep.outputFile=build/conversion-classpath.txt'
$conversionClasspath = 'target/test-classes;target/classes;' + (Get-Content build/conversion-classpath.txt -Raw).Trim()
& "$env:JAVA_HOME/bin/java.exe" -cp $conversionClasspath `
  dev.parseforge.infrastructure.engine.ConversionOutputSmoke `
  markitdown "$env:LOCALAPPDATA/ParseForge" 'C:/path/to/fixture.pdf' build/conversion-smoke
```

Replace `markitdown` with `marker` to exercise Marker. Evidence is written under
a unique folder in `build/conversion-smoke`; fixture originals are never modified.

## Remaining performance work

Output discovery now scales with the files generated by the current conversion,
rather than all historical exports. No percentage improvement in end-to-end
conversion time is claimed. The managed Marker command still starts Python and
loads models for every document. Reusing a worker could reduce repeated startup
cost, but needs separate memory, cancellation, crash-recovery and offline tests
before adoption. The OCR algorithms and model configuration are unchanged.
